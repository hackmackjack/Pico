## 1. Project 1701: Professional PID Temp Control Driver Implementation

### 2. Learning Objective
Implement a Proportional (P) Controller to regulate temperature. Learn how to drive a heating element using PWM based on sensor feedback.

### 3. Concepts Introduced
*   **Feedback Loop**: Continuously reading the output (Temp) to adjust input (Power).
*   **Proportional Control (P)**: The harder you push, the faster it corrects. Output is proportional to Error.
*   **Thermal Inertia**: Heaters don't heat up instantly; there is lag.

### 4. Hardware Required
*   **Raspberry Pi Pico**
*   **Heater** (Resistor or Light Bulb)
*   **Thermistor** (Temperature Sensor)
*   **MOSFET Module** (To drive the heater)

### 5. Wiring / Interfaces
*   **Thermistor** -> GP26 (ADC0)
*   **MOSFET Gate** -> GP15 (PWM)

### 6. Blocks Used
*   **from Sensing, drag `read_adc`**
*   **from Motion & Motors, drag `set_pwm`**
*   **from Math, drag `calculation`**

### 7. Variables
*   **target_temp** (Number): Desired setpoint (e.g., 40.0 C).
*   **kp** (Number): Proportional Gain constant.
*   **error** (Number): Difference between Target and Actual.

### 8. Step-by-Step Guide

**A. Setup**
1.  **Sensor**: Configure ADC on GP26.
2.  **Actuator**: Configure PWM on GP15 (Heater). Low frequency (10Hz) is better for thermal heaters than high frequency.

**B. Control Loop**
1.  **Measure**: Read Thermistor. Convert to Celsius.
2.  **Calculate Error**: `Error = Target - Current`.
3.  **Apply P-Term**: `Duty = Error * Kp`.
4.  **Clamp**: Ensure Duty is between 0 and 65535.
5.  **Output**: Write Duty to Heater.

### 9. Execution Flow
1.  **Start**: Temp is 25C. Target is 40C. Error is 15.
2.  **Action**: Heater creates substantial heat (High Duty).
3.  **Rise**: Temp rises to 35C. Error is 5.
4.  **Settle**: Heater reduces power.
5.  **Steady State**: Temp stabilizes near 40C (with some "Static Error" typical of P-only controllers).

### 10. Generated Code
``python
from machine import ADC, PWM, Pin
import time

thermistor = ADC(26)
heater = PWM(Pin(15))
heater.freq(10) # Slow PWM for heater (reduced switching loss)

target_temp = 40.0
kp = 5000 # Gain: Needs Tuning!

while True:
    raw = thermistor.read_u16()
    # Approx conversion for 10k thermistor (Simplified linear model)
    # Calibrate this for your specific sensor!
    temp = 27 - (raw - 10000) / 500 
    
    error = target_temp - temp
    
    # Proportional Calculation
    duty = int(error * kp)
    
    # Clamping (Safety)
    if duty < 0: duty = 0
    if duty > 65535: duty = 65535
    
    heater.duty_u16(duty)
    time.sleep(0.1)
``

### 11. Common Mistakes
*   **Wrong Gain (Kp)**: If Kp is too high, it oscillates wildy. If too low, it never reaches the target.
*   **PWM Frequency**: Driving a relay or large MOSFET at 100kHz causes overheating. Use < 100Hz for heaters.

### 12. Try This Next
*   **Tuning**: Double `kp`. Does it overshoot? Halve `kp`. Is it too slow?
*   **Cooler**: Invert the logic to drive a Fan instead of a Heater.

## 1. Project 1702: Asynchronous Professional PID Temp Control Handler

### 8. Step-by-Step Guide

**A. Define Loop**
1.  **Function**: `temp_loop()`.
2.  **Logic**: Copy PID logic from Project 1701.
3.  **Wait**: `await asyncio.sleep(1)`.

**B. Scheduler**
1.  **Main**: Create Task `temp_loop`.
2.  **Run**: Start Event Loop.

### 9. Execution Flow
1.  **Tick 0s**: PID runs. Sets Heater. Sleeps.
2.  **Tick 0.1s**: Main program updates Screen/UI.
3.  **Tick 1.0s**: PID wakes up. Reads Temp. Adjusts Heater. Sleeps.
4.  **Benefit**: UI remains responsive.

### 10. Generated Code
``python
import uasyncio as asyncio

# Assume heater/thermistor setup globally

async def temp_loop():
    print("Starting Thermal Control...")
    while True:
        # 1. Read
        raw = thermistor.read_u16()
        temp = 27 - (raw - 10000) / 500
        
        # 2. Calc
        error = target_temp - temp
        duty = int(error * kp)
        if duty < 0: duty = 0
        if duty > 65535: duty = 65535
        
        # 3. Write
        heater.duty_u16(duty)
        # print(f"Temp: {temp:.1f} Duty: {duty}")
        
        # 4. Yield
        await asyncio.sleep(1) # Run only once per second

# Usage:
# loop = asyncio.get_event_loop()
# loop.create_task(temp_loop())
# loop.run_forever()
``

### 11. Common Mistakes
*   **Time.sleep()**: Using standard `time.sleep()` inside an async function blocks the *entire* CPU. Always use `await asyncio.sleep()`.

## 1. Project 1703: Object-Oriented Professional PID Temp Control Class

### 2. Learning Objective
Encapsulate the thermal logic into a reusable `Thermostat` component. This allows you to control multiple heaters (e.g., 3D Printer Extruder + Bed) easily.

### 3. Concepts Introduced
*   **Encapsulation**: Hiding the math (Kp, limits) inside the class. The user just says "Set Target".
*   **Bang-Bang Control**: A simple alternative to PID (On if Cold, Off if Hot).

### 4. Hardware Required
*   **Raspberry Pi Pico**

### 5. Wiring / Interfaces
*   (Internal)

### 6. Blocks Used
*   **from Classes, drag `define_class`**

### 7. Variables
*   **sp** (Setpoint): The target temperature.

### 8. Step-by-Step Guide

**A. Class Definition**
1.  **Init**: Store standard settings (Setpoint, Hysteresis).
2.  **Method**: `set_setpoint(temp)`.
3.  **Method**: `update(current_temp)` -> returns Output State (On/Off).

**B. Instantiation**
1.  `bed = Thermostat(60)`
2.  `nozzle = Thermostat(200)`

### 9. Execution Flow
1.  **Loop**: Read Bed Temp -> `bed.update(t1)`. Read Nozzle Temp -> `nozzle.update(t2)`.
2.  **Logic**: Each object maintains its own internal state independent of others.

### 10. Generated Code
``python
class Thermostat:
    def __init__(self, sp, hysteresis=1.0):
        self.sp = sp
        self.hysteresis = hysteresis
        self.output = 0
        
    def set_setpoint(self, t):
        self.sp = t
        
    def update(self, current_temp):
        # Bang-Bang with Hysteresis
        if current_temp < (self.sp - self.hysteresis):
            self.output = 1 # ON
        elif current_temp > (self.sp + self.hysteresis):
            self.output = 0 # OFF
        
        # Return 1 or 0 for GPIO
        return self.output

# Usage
t_stat = Thermostat(40.0)
state = t_stat.update(38.5)
``

### 11. Common Mistakes
*   **Global Variables**: Using global variables inside a class method defeats the purpose of OOP. Use `self.variable`.
*   **Rapid Switching**: Without hysteresis, "Bang-Bang" control will toggle the relay 50 times a second at the setpoint, destroying it.

### 12. Try This Next
*   **PID Class**: Upgrade the class from Bang-Bang to full PID math.
*   **Auto-Off**: Add a `timer` to the class to shut off after 1 hour.

## 1. Project 1704: Robust Professional PID Temp Control Controller

### 2. Learning Objective
Understand the "D" (Derivative) in PID. Prevent overshoot (heating past the target) by predicting the future temperature curve.

### 3. Concepts Introduced
*   **Overshoot**: When momentum carries the temp past the target (e.g., hitting 110C when set to 100C).
*   **Damping**: Applying "brakes" as you approach the target.
*   **Derivative Term**: `D = (Error - Previous_Error)`. Measures speed of change.

### 4. Hardware Required
*   **Raspberry Pi Pico**

### 5. Wiring / Interfaces
*   (Internal)

### 6. Blocks Used
*   **from Math, drag `basic_operations`**
*   **from Variables, drag `global_var`**

### 7. Variables
*   **prev_error** (Number): Memory of the last loop.
*   **kd** (Number): Derivative Gain.

### 8. Step-by-Step Guide

**A. Calculation**
1.  `P = Error * Kp`.
2.  `D = (Error - Last_Error) * Kd`.
3.  `Output = P + D`.

**B. Physics Logic**
1.  If approaching target fast: Error is shrinking. `(Error - Last)` is negative. `D` is negative. This subtracts from Output.
2.  **Result**: Heater turns down *before* hitting the target.

### 9. Execution Flow
1.  **Start**: Temp rising fast. P is High. D is Negative (Braking).
2.  **Approach**: 5 degrees away. P says "Push". D says "Slow down!".
3.  **Arrival**: Temp lands softly on 100C without going over.

### 10. Generated Code
``python
# Variables needed for D-term
prev_error = 0
kd = 1000 # Damping factor

# Inside Loop:
error = target_temp - temp
    
# P Term
p_term = error * kp
    
# D Term (Change in error)
d_term = (error - prev_error) * kd
prev_error = error # Save for next time
    
# Combined
duty = int(p_term + d_term)
``

### 11. Common Mistakes
*   **Noise Amplification**: D-term hates noise. If sensor jumps 0.1C due to electrical noise, `Calculated Speed` looks infinity. Use averaging (Project 1709) before D-calc.
*   **Derivative Kick**: Changing the setpoint causes a massive spike in Error, leading to a massive D-Kick.

### 12. Try This Next
*   **I-Term**: Add Integral (I) to fix steady-state error. `I = I + Error`.
*   **Plotting**: Graph P, I, and D terms separately to see what each is doing.

### 8. Step-by-Step Guide

2.  **Effect**: Heat loss increases by 50%.

**B. Compensate**

### 9. Execution Flow

2.  **Event**: User opens oven door.
3.  **Action**: Code adds 5000. Total Output 15000.

### 10. Generated Code

### 3. Concepts Introduced

*   **Soft Limit**: Code restriction.
*   **Power Budget**: Limiting total current draw (e.g., USB port limit).

**B. Clamp Logic**

MAX_POWER_PERCENT = 80
MAX_PWM = int(65535 * (MAX_POWER_PERCENT / 100.0))

def update_heater(duty_request):
    # Security Check
    if duty_request > MAX_PWM:
        print(f"Limiting Power: {duty_request} -> {MAX_PWM}")

## 1. Project 1709: Multi-Threaded Professional PID Temp Control

### 2. Learning Objective
Separate the Sensor Reading (High Speed, Precision) from the User Interface (Low Speed). Use Core 1 for the math loop.

### 3. Concepts Introduced
*   **Oversampling**: Reading a noisy sensor 100 times and averaging it to get a cleaner signal. Requires CPU time.
*   **Race Condition**: What happens if Core 0 reads `temp` while Core 1 is writing it? (Atomic operations).

### 4. Hardware Required
*   **Raspberry Pi Pico**

### 5. Wiring / Interfaces
*   (Internal)

### 6. Blocks Used
*   **from Threading, drag `start_core1`**
*   **from Variables, drag `global`**

### 7. Variables
*   **shared_temp** (Float): Accessible by both cores.

### 8. Step-by-Step Guide

**A. Core 1 (Worker)**
1.  **Loop**: Run at 1kHz.
2.  **Action**: Read ADC. Add to rolling average.
3.  **Update**: Write to `shared_temp`.

**B. Core 0 (Main)**
1.  **Loop**: Run at 1Hz.
2.  **Action**: Read `shared_temp`. Update Screen. Print Log.

### 9. Execution Flow
1.  **Core 1**: Churns through data. Filters out noise spikes (`[10, 10, 100, 10] -> 32`).
2.  **Core 0**: Sees a stable float value.
3.  **Result**: Extremely smooth control without UI lag.

### 10. Generated Code
``python
import _thread
import machine
import utime

# Shared Memory
shared_temp = 0.0
lock = _thread.allocate_lock()

def core1_task():
    global shared_temp
    adc = machine.ADC(26)
    while True:
        # Oversample 100 times
        total = 0
        for _ in range(100):
            total += adc.read_u16()
            utime.sleep_us(100)
            
        avg = total / 100
        
        # Update shared var safely
        t_calc = 27 - (avg - 10000) / 500
        with lock:
            shared_temp = t_calc
            
# Start Core 1
_thread.start_new_thread(core1_task, ())

# Main Thread (Core 0)
while True:
    with lock:
        current_t = shared_temp
        
    print(f"Precise Temp: {current_t:.2f}")
    utime.sleep(0.5)
``

### 11. Common Mistakes
*   **ADC Conflict**: RP2040 has one ADC. If both cores try to read it simultaneously, it might crash or give garbage. Best to dedicate hardware to one core.
*   **Locking**: For a simple float, locking is rarely strictly needed in MicroPython (atomic-ish), but good practice for larger data structures.

### 12. Try This Next
*   **Parallel PID**: Handle 2 Heaters. Core 0 handles Heater A, Core 1 handles Heater B.
*   **Watchdog**: Have Core 0 check if Core 1 is still updating `shared_temp` timestamp. If not, Core 1 crashed.

## 1. Project 1710: Industrial Professional PID Temp Control Solution

### 2. Learning Objective
Project: Build a **Sous Vide** controller. This requires extremely high precision (+/- 0.1C) to cook steak perfectly. Combines all previous concepts: PID, Tuning, Safety, and Averaging.

### 3. Concepts Introduced
*   **Integral (I) Term**: Removes "Steady State Error". P-only always leaves a gap. I-term pushes it that last 1%.
*   **Windup Guard**: preventing I-term from accumulating during warm-up.

### 4. Hardware Required
*   **Raspberry Pi Pico**
*   **Water Bath Setup** (Heater + Pump + Sensor)

### 5. Wiring / Interfaces
*   **Pump** -> GP14 (Always On during cook)
*   **Heater** -> GP15 (PWM)

### 6. Blocks Used
*   **from Math, drag `PID_Algorithm`** (Custom Block)

### 7. Variables
*   **Ki** (Integral Gain): Very small value (e.g., 0.1).
*   **integral_sum** (Accumulator).

### 8. Step-by-Step Guide

**A. Full PID Math**
1.  `Error = Target - Actual`.
2.  `P = Error * Kp`.
3.  `I_sum += Error`.
4.  `I = I_sum * Ki`.
5.  `D = (Error - Last) * Kd`.
6.  `Output = P + I + D`.

**B. Tuning**
1.  Start Kp until it oscillates.
2.  Add Kd to dampen oscillation.
3.  Add Ki to close the final gap.

### 9. Execution Flow
1.  **Cold Start**: P and I terms grow. Heater 100%.
2.  **Near Target**: P drops. I takes over to maintain heat loss.
3.  **Steady**: Output sits at exactly 32% to match heat loss. Temp is rock solid at 55.0C.

### 10. Generated Code
``python
# Constants
Kp = 2000
Ki = 5.0
Kd = 5000

# State
integral = 0
prev_error = 0

while True:
    # 1. Read (Averaged)
    temp = read_precise_temp()
    
    # 2. Error
    error = target_temp - temp
    
    # 3. I-Term (with Windup Limit)
    integral += error
    if integral > 10000: integral = 10000
    if integral < -10000: integral = -10000
    
    # 4. PID Calc
    p = error * Kp
    i = integral * Ki
    d = (error - prev_error) * Kd
    
    output = int(p + i + d)
    
    # 5. Actuate
    if output < 0: output = 0
    if output > 65535: output = 65535
    heater.duty_u16(output)
    
    prev_error = error
    time.sleep(0.1)
``

### 11. Common Mistakes
*   **I-Windup**: If you don't cap `integral`, waiting for water to boil (20 mins) builds up massive Integral. When you reach target, it keeps heating for another 10 mins.
*   **Pump Failure**: If water stops moving, heater boils locale water instantly. Use a Flow Switch flow interlock.

### 12. Try This Next
*   **Auto-Tune**: Write code that measures the heater's response curve and calculates Kp/Ki/Kd automatically.
*   **Smart Display**: Add an LCD to show Setpoint vs Actual.

## Batch 172: Professional Motion Profiling (Ramp) 1 (9-12 (High School))

### Project 1711: Professional Motion Profiling (Ramp) Driver Implementation

### 2. Learning Objective
Implement a **Trapezoidal Motion Profile** (Acceleration, Cruise, Deceleration) to enable smooth motor movements. Learn why sudden starts/stops cause mechanical wear.

### 3. Concepts Introduced
*   **Kinematics**: Reviewing Physics 101 equations: `v = a*t`, `d = 1/2*a*t^2`.
*   **Jerk**: The rate of change of acceleration. Infinite jerk (instant start) damages gearboxes.
*   **Cruise Phase**: The period of constant velocity travel.

### 4. Hardware Required
*   **Raspberry Pi Pico**
*   **Motor Driver** (Stepper or DC with Encoder)
*   **Motor**

### 5. Wiring / Interfaces
*   **PWM/Step Pin** -> GP16
*   **Dir Pin** -> GP17

### 6. Blocks Used
*   **from Motion, drag `set_velocity`**
*   **from Math, drag `compare`**

### 7. Variables
*   **accel** (Number): Acceleration rate (units/sec^2).
*   **max_vel** (Number): Top speed.
*   **current_vel** (Number): Current speed.

### 8. Step-by-Step Guide

**A. Physics Setup**
1.  **Ramp Up**: Velocity increases linearly until `max_vel`.
2.  **Cruise**: Velocity stays at `max_vel`.
3.  **Ramp Down**: Velocity decreases linearly to 0 as target approaches.

**B. Calculation Loop**
1.  Determine `accel_dist` (Distance needed to reach top speed).
2.  If `remaining_dist < decel_dist`: Slow down.
3.  Else if `current_vel < max_vel`: Speed up.
4.  Else: Maintain Speed.

### 9. Execution Flow
1.  **Start**: Motor buzzes, pitch rises (Acceleration).
2.  **Middle**: Steady hum (Cruise).
3.  **End**: Pitch falls (Deceleration).
4.  **Result**: Robot moves 1 meter without tipping over.

### 10. Generated Code
``python
# Constants
accel = 10     # speed units per loop
max_vel = 1000 # top speed
decel = 10

target_pos = 5000
current_vel = 0
current_pos = 0

while abs(current_pos - target_pos) > 0:
    dist_remaining = abs(target_pos - current_pos)
    
    # Calculate stopping distance needed at current speed
    # d = v^2 / (2a)
    stopping_dist = (current_vel * current_vel) / (2 * decel)
    
    if dist_remaining <= stopping_dist:
        # Decel Phase
        current_vel -= decel
    elif current_vel < max_vel:
        # Accel Phase
        current_vel += accel
    else:
        # Cruise Phase
        current_vel = max_vel
        
    if current_vel < 10: current_vel = 10 # Minimum crawl
    
    # Move
    current_pos += current_vel
    # set_motor_speed(current_vel)
    print(f"Vel: {current_vel} Pos: {current_pos}")
``

### 11. Common Mistakes
*   **Math Errors**: Calculating `stopping_dist` incorrectly leads to overshooting the target or stopping too early (creeping).
*   **Integer Overflow**: `current_vel * current_vel` can exceed 65535 or 2 billion quickly. Use proper variable types.

### 12. Try This Next
*   **S-Curve**: Instead of linear lines, use Sinewaves for acceleration (Project 1714) for smoother motion.
*   **XY Interp**: Coordinate X and Y amps to draw a circle.

### 3. Concepts Introduced

*   **Pico**

### 8. Step-by-Step Guide

2.  Read `encoder_val`.
3.  `err = abs(next_setpoint - encoder_val)`.

## Batch 173: Professional Sensor Fusion (IMU) 1 (9-12 (High School))

### Project 1721: Professional Sensor Fusion (IMU) Driver Implementation

### 2. Learning Objective
Interface with an MPU6050 Accelerometer/Gyroscope. Learn how to convert raw "LSB" (Least Significant Bits) integers into useful physical units like *g* (Gravity) and *deg/s* (Rotation Speed).

### 3. Concepts Introduced
*   **MEMS**: Micro-Electro-Mechanical Systems. Tiny silicon springs inside the chip measure force.
*   **Sensitivity Scale**: The sensor can be set to +/- 2g, 4g, 8g, or 16g. The default 2g gives highest precision for tilt, but clips during impacts.
*   **I2C**: The standard communication protocol used by most sensors.

### 4. Hardware Required
*   **Raspberry Pi Pico**
*   **MPU6050 Module** (GY-521)
*   **Breadboard & Jumper Wires**

### 5. Wiring / Interfaces
*   **VCC** -> 3.3V
*   **GND** -> GND
*   **SDA** -> GP0 (I2C0 SDA)
*   **SCL** -> GP1 (I2C0 SCL)

### 6. Blocks Used
*   **from Sensing, drag `read_i2c_register`**
*   **from Math, drag `division`**

### 7. Variables
*   **raw_x** (Integer): The 16-bit value from the sensor (-32768 to 32767).
*   **scale_factor** (Float): 16384.0 (for +/- 2g setting).

### 8. Step-by-Step Guide

**A. Initialization**
1.  Wake up the MPU6050 (Write `0` to Power Mgmt Register `0x6B`).
2.  Set Scale (default is usually fine).

**B. Read Loop**
1.  Read 2 bytes starting at Register `0x3B` (Accel X).
2.  Combine High and Low bytes into signed 16-bit integer.
3.  Divide by Scale Factor.

### 9. Execution Flow
1.  **Stationary**: Accel Z reads ~1.00g (Gravity). X and Y read ~0.00.
2.  **Tilt**: Tilting the sensor mixes Gravity into X and Y axes.
3.  **Shake**: Numbers spike to >2.00g.

### 10. Generated Code
``python
from machine import I2C, Pin
import struct
import time

i2c = I2C(0, sda=Pin(0), scl=Pin(1), freq=400000)
ADDR = 0x68

# Wake up
i2c.writeto_mem(ADDR, 0x6B, b'\x00')

while True:
    # Read 6 bytes (Accel X, Y, Z) starting at 0x3B
    data = i2c.readfrom_mem(ADDR, 0x3B, 6)
    
    # Unpack 3 signed shorts (>h)
    raw_x, raw_y, raw_z = struct.unpack(">hhh", data)
    
    # Convert to G force (2g scale = 16384 LSB/g)
    acc_x = raw_x / 16384.0
    acc_y = raw_y / 16384.0
    acc_z = raw_z / 16384.0
    
    print(f"X:{acc_x:.2f} Y:{acc_y:.2f} Z:{acc_z:.2f}")
    time.sleep(0.1)
``

### 11. Common Mistakes
*   **Address Confusion**: AD0 pin determines if address is 0x68 or 0x69. If "OSError: [Errno 5] EIO" occurs, check wiring and address.
*   **Endianness**: Using `<` (Little Endian) instead of `>` (Big Endian) in `struct.unpack` will result in chaotic numbers.

### Project 1722: Asynchronous Professional Sensor Fusion (IMU) Handler

### 2. Learning Objective
Maintain a stable **Sampling Rate** (e.g., 100Hz). Integrating noise over non-uniform time steps ruins the accuracy of sensor fusion. Using Async ensures timing consistency.

### 3. Concepts Introduced
*   **Jitter**: Variation in the time between samples. Jitter causes drift in integration (`Angle += Gyro * dt`).
*   **Yield**: Returning control to the scheduler so other tasks can run during the wait.

### 4. Hardware Required

### 5. Wiring / Interfaces

### 6. Blocks Used
*   **from Async, drag `define_task`**
*   **from Smart IO, drag `ticks_diff`**

### 7. Variables
*   **next_run**: Timestamp for when the next sample *should* occur.

### 8. Step-by-Step Guide

**A. Task Loop**
1.  Initialize `next_run = now()`.
2.  Loop Forever.
3.  Check: `if now() >= next_run`.
4.  IF YES: Read Sensor. Increment `next_run += 10ms`.
5.  Yield (`await asyncio.sleep(0.001)`).

1.  **Tick 100ms**: Read. Next = 110ms.
2.  **Tick 102ms**: Sleep.
3.  **Tick 110ms**: Read. Next = 120ms.

async def imu_task():
    print("IMU 100Hz Measurement Started")
    next_run = time.ticks_ms()
    while True:
        # Check if it's time specifically
        if time.ticks_diff(time.ticks_ms(), next_run) > 0:
            # 1. READ
            # read_imu() 
            
            # 2. SCHEDULE
            next_run += 10 # 10ms = 100Hz TARGET
            
            # 3. Warning (Optional)
            if time.ticks_diff(time.ticks_ms(), next_run) > 0:
                print("Lag detected! CPU Overload.")

        await asyncio.sleep_ms(1)

# Usage:
# loop.create_task(imu_task())

### Project 1724: Robust Professional Sensor Fusion (IMU) Controller

### 2. Learning Objective
Implement a **Complementary Filter**. This is the simplest way to fuse Gyroscope (Fast but Drifts) and Accelerometer (Noisy but Stable) data to get a clean Angle.

### 3. Concepts Introduced
*   **Gyro Drift**: Gyros measure rate. Integrating drift (`sum += rate`) accumulates error over time (e.g., 1 degree per minute).
*   **High/Low Pass**: Accelerometer is "Low Frequency" (Gravity). Gyro is "High Frequency" (Movement).
*   **Fusion**: `0.98 * Gyro + 0.02 * Accel`.

### 4. Hardware Required
*   **Pico**
*   **MPU6050**

### 5. Wiring / Interfaces
*   (Internal)

### 6. Blocks Used
*   **from Math, drag `calculation`**

### 7. Variables
*   **alpha** (Float): Filter weight (0.98 is standard).
*   **dt** (Float): Time step (0.01s for 100Hz).

### 8. Step-by-Step Guide

**A. Read Sensors**
1.  `acc_angle = atan2(y, z)`. (Angle from Gravity).
2.  `gyro_rate = read_gyro()`.

**B. Filter**
1.  `angle = alpha * (angle + gyro_rate * dt) + (1-alpha) * acc_angle`.

### 9. Execution Flow
1.  **Fast Move**: Gyro allows angle to change instantly.
2.  **Stand Still**: Gyro says "0", but might drift. Accelerometer slowly pulls the angle back to "True Down" via the 0.02 weight.
3.  **Result**: Clean, responsive angle without drift.

### 10. Generated Code
``python
import math

angle_x = 0.0
alpha = 0.98
dt = 0.01 # 100Hz

while True:
    # 1. Read
    acc_y = read_acc_y()
    acc_z = read_acc_z()
    gyro_x = read_gyro_x()
    
    # 2. Accel Angle (Simplified for small tilts)
    acc_angle_x = math.atan2(acc_y, acc_z) * 57.296
    
    # 3. Filter
    # (Previous + Change) * 98%  +  (Gravity Reference) * 2%
    angle_x = alpha * (angle_x + gyro_x * dt) + (1.0 - alpha) * acc_angle_x
    
    print(f"Fused Angle: {angle_x:.1f}")
    time.sleep(dt)
``

### 11. Common Mistakes
*   **Units**: Adding `Degrees` (Accel) to `Radians` (Gyro) works poorly. Convert everything to Degrees first.
*   **Loop Time**: If `time.sleep(dt)` is inaccurate, the integration `gyro * dt` will be wrong. PID/IMU code should measure actual `dt` using `ticks_us()`.

*   **Kalman Filter**: The "Pro" version of this. Requires matrix math (difficult on Pico without `ulab`), but optimally estimates state.

### Project 1731: Professional Statistical Analysis (Edge) Driver Implementation

### 2. Learning Objective
Implement a **Running Average** (Moving Average) to smooth out noisy sensor data. Learn the trade-off between "Smoothness" (Large N) and "Responsiveness" (Small N).

### 3. Concepts Introduced
*   **Noise**: Random fluctuations in signal (e.g., ADC reading 4095, 4090, 4100).
*   **Window**: The number of recent samples considered (N).
*   **Ring Buffer**: An efficient way to store the "Last N" samples without copying arrays.

### 4. Hardware Required
*   **Raspberry Pi Pico**
*   **Potentiometer** (to generate signal)

### 5. Wiring / Interfaces
*   **Potentiometer Pin** -> GP26 (ADC0)

### 6. Blocks Used
*   **from Lists, drag `set_item`**
*   **from Math, drag `division`**

### 7. Variables
*   **window_size**: N (e.g., 10).
*   **samples**: List of size N.

### 8. Step-by-Step Guide

**A. Logic**
1.  New Sample arrives ($X_{new}$).
2.  Subtract oldest sample ($X_{old}$) from Sum.
3.  Add new sample to Sum.
4.  Overwrite oldest in list.
5.  `Avg = Sum / N`.

**B. Why?**
1.  Summing the whole list every time is slow ($O(N)$).
2.  keeping a running sum is fast ($O(1)$).

### 9. Execution Flow
1.  **Input**: 10, 10, 10, 20.
2.  **Avg**: Slowly climbs from 10 to 12.5 to 15...
3.  **Result**: Sudden spikes are flattened.

### 10. Generated Code
``python
class MovingAverage:
    def __init__(self, n):
        self.n = n
        self.samples = [0] * n
        self.idx = 0
        self.sum = 0
        
    def update(self, new_val):
        old_val = self.samples[self.idx]
        
        # Update Sum efficiently
        self.sum = self.sum - old_val + new_val
        
        # Overwrite buffer
        self.samples[self.idx] = new_val
        
        # Increment index circular
        self.idx = (self.idx + 1) % self.n
        
        return self.sum / self.n

# Usage
ma = MovingAverage(10)
print(ma.update(100))
print(ma.update(102))
``

### 11. Common Mistakes
*   **Floating Point Drift**: Repeatedly adding/subtracting floats can accumulate tiny errors ($0.1 + 0.2 \neq 0.3$). Occasionally recalculate the full sum from scratch to "reset" the error.
*   **Initialization**: The average starts at 0. It takes N samples to "warm up" to the real value.

### 12. Try This Next
*   **Exponential Moving Average (EMA)**: `Avg = Alpha * New + (1-Alpha) * Avg`. Uses less RAM (no list) but has infinite memory.

### Project 1736: Optimized Professional Statistical Analysis (Edge) Algorithm

### 2. Learning Objective
Implement **Welford's Algorithm**. This is the professional standard for calculating Variance and Standard Deviation in a **single pass** (online).

### 3. Concepts Introduced
*   **One-Pass vs Two-Pass**: Standard variance requires calculating Mean first (Pass 1), then Diff Squared (Pass 2). This requires storing all data.
*   **Online Algorithm**: Updates the Variance incrementally with each new number.

### 4. Hardware Required
*   **Pico**

### 5. Wiring / Interfaces
*   (Internal)

### 6. Blocks Used
*   **from Math, drag `calculation`**

### 7. Variables
*   **M2**: The sum of squares of differences from the current mean.

### 8. Step-by-Step Guide

**A. Init**
1.  `mean = 0`, `M2 = 0`, `count = 0`.

**B. Update (New X)**
1.  `count += 1`.
2.  `delta = X - mean`.
3.  `mean += delta / count`.
4.  `delta2 = X - mean`. (Note: Mean has changed!)
5.  `M2 += delta * delta2`.

**C. Result**
1.  `Variance = M2 / (count - 1)`.

### 9. Execution Flow
1.  **Stream**: 1, 3, 5.
2.  **Step 1**: Mean 1, M2 0.
3.  **Step 2**: Mean 2, M2 2.
4.  **Step 3**: Mean 3, M2 8.
5.  **Final**: Var = 8/2 = 4. Correct.

### 10. Generated Code
``python
# Online Mean/Variance (Welford)
count = 0
mean = 0
M2 = 0

def update(new_x):
    global count, mean, M2
    count += 1
    delta = new_x - mean
    mean += delta / count
    delta2 = new_x - mean
    M2 += delta * delta2
    
    if count < 2: return 0.0
    return M2 / count # Use (count-1) for Sample Variance

# Test
import random
for _ in range(10):
    val = random.randint(0, 100)
    var = update(val)
    print(f"Val: {val} Mean: {mean:.1f} Var: {var:.1f}")
``

### 11. Common Mistakes
*   **Sample vs Population**: Divide by `N` for Population Variance, `N-1` for Sample Variance.
*   **Confusion**: Understanding *why* `delta * delta2` works is deep math. Just trust Welford.

### Project 1746: Optimized Professional Data Compression (RLE) Algorithm

### 2. Learning Objective
Implement **Bit Packing**. Often we have boolean flags (True/False). Storing them as 1 Byte each is wasteful. We can pack 8 bools into 1 Byte.

### 3. Concepts Introduced
*   **Bitmask**: Using `&`, `|`, `<<` to access specific bits.
*   **Payload Efficiency**: 87.5% reduction in size.

### 4. Hardware Required
*   **Pico**

### 5. Wiring / Interfaces
*   (Internal)

### 6. Blocks Used
*   **from Math, drag `bitwise_or`**

### 7. Variables
*   **packed_byte**: The 8-bit integer holding 8 flags.

### 8. Step-by-Step Guide

**A. Input**
1.  List: `[True, False, True, False, False, False, False, False]`.

**B. Loop**
1.  If `List[0]` is True: `Byte = Byte | 1`.
2.  If `List[1]` is True: `Byte = Byte | 2`.
3.  If `List[2]` is True: `Byte = Byte | 4`.

### 9. Execution Flow
1.  **Start**: 0000 0000.
2.  **Bit 0**: True. 0000 0001.
3.  **Bit 2**: True. 0000 0101 (Decimal 5).

### 10. Generated Code
``python
flags = [True, False, True, True, False, False, False, True]

def pack_flags(flag_list):
    byte_val = 0
    for i, active in enumerate(flag_list):
        if active:
            # Shift 1 to the left by i positions
            byte_val |= (1 << i)
    return byte_val

def unpack_flags(byte_val):
    res = []
    for i in range(8):
        # Check if bit i is set
        is_set = (byte_val >> i) & 1
        res.append(bool(is_set))
    return res

p = pack_flags(flags)
print(f"Packed: {bin(p)}")
u = unpack_flags(p)
print(f"Match: {u == flags}")
``

### 11. Common Mistakes
*   **Endianness**: Is Bit 0 the start or end of the list? Just be consistent.
*   **Range**: Can only pack 8 items per byte. For 9 items, you need 2 bytes.

### 12. Try This Next
*   **Struct**: Use Python's `struct` module for packing C-style binary data.

### Project 1750: Industrial Professional Data Compression (RLE) Solution

### 2. Learning Objective
Implement **Delta Encoding** combined with RLE. This is highly effective for sensor data. Instead of storing `[100, 101, 102, 102]`, store differences `[100, +1, +1, +0]`. Then RLE compresses the `+0`s.

### 3. Concepts Introduced
*   **Delta**: Difference between current and previous value.
*   **Chain Compression**: Applying Alg A then Alg B.

### 4. Hardware Required

### 5. Wiring / Interfaces
*   (Internal)

### 6. Blocks Used
*   **from Math, drag `subtraction`**

### 7. Variables
*   **last_val**: The reference.

### 8. Step-by-Step Guide

**A. Delta**
1.  Input: 50, 51, 51, 51, 52.
2.  Deltas: 50, +1, 0, 0, +1.

**B. RLE**
1.  Encode Deltas: `1x50, 1x1, 2x0, 1x1`.

**C. Decode**
1.  Start 0. Add 50 -> 50. Add 1 -> 51. Add 0 -> 51...

### 9. Execution Flow
1.  **Sensor**: Temperature is very stable.
2.  **Deltas**: Mostly 0s.
3.  **RLE**: Compresses 0s extremely well.
4.  **Result**: High compression ratio for slow-moving data.

### 10. Generated Code
``python
def delta_encode(samples):
    if not samples: return []
    
    deltas = []
    last = 0 # Assume start at 0
    
    for s in samples:
        diff = s - last
        deltas.append(diff)
        last = s
        
    return deltas

def delta_decode(deltas):
    samples = []
    val = 0
    
    for d in deltas:
        val += d
        samples.append(val)
        
    return samples

orig = [10, 11, 11, 11, 12, 10]
d = delta_encode(orig)
print(f"Deltas: {d}") # [10, 1, 0, 0, 1, -2]
rec = delta_decode(d)
print(f"Recovered: {rec}")
``

### 11. Common Mistakes
*   **Accumulated Error**: If one delta is corrupt (`+1` becomes `+5`), *every* subsequent value is shifted by 4. Delta encoding propagates errors. Frequent "Keyframes" (absolute values) fix this.

### 12. Try This Next
*   **ZigZag Encoding**: Map negative deltas to positive integers so standard VarInt encoding works better.

*   **I2C Sensor** (Any, or simulate failure)

### 6. Blocks Used
*   **from Logic, drag `try_except`**

### 7. Variables
*   **attempt**: Counter (0..3).

### 8. Step-by-Step Guide

**A. Logic**
1.  Loop 3 times.
2.  `Try` to read sensor.
3.  If success: Return Data.
4.  `Except OSError`: Wait 10ms. Continue Loop.
5.  If Loop finishes without success: Return `None`.

**B. Execution Flow**
1.  **Attempt 1**: `OSError` (Noise).
2.  **Wait**: Sleep 10ms.
3.  **Attempt 2**: Success!
4.  **Result**: Code continues running. User never notices the glitch.

            # Simulate generic read
            data = i2c.readfrom(addr, 1)
            return data
        except OSError as e:

            time.sleep(0.01) # Short pause

    return None

# Main Loop

### 7. Variables

### 8. Step-by-Step Guide

**A. Init**

**B. Loop**
1.  `wdt.feed()`.
2.  Do work.

**C. Failure**
1.  `try: ... except Critical: while True: pass`.
2.  Infinite loop stops feeding wdt.
3.  2 seconds later -> Hard Reboot.

### 9. Execution Flow
1.  **Normal**: Feed... Feed... Feed.

``python

# CAUTION: If your code sleeps > 3s, it will reboot!
wdt = WDT(timeout=3000)

print("System Booted.")

try:
    for i in range(10):
        print(f"Working {i}...")
        wdt.feed() # I am alive
        time.sleep(0.5)

wlan.connect(ssid, pw, bssid=target_bssid)

max_wait = 10
while max_wait > 0:
    if wlan.status() < 0 or wlan.status() >= 3:
        break
    max_wait -= 1
    print('waiting for connection...')
    time.sleep(1)

if wlan.status() != 3:
    raise RuntimeError('network connection failed')
else:
    print('connected')
    status = wlan.ifconfig()
    print( 'ip = ' + status[0] )
``

### 11. Common Mistakes
*   **Wrong Format**: BSSID must be bytes `b'...'`, not a String `"..."`. Use `ubinascii.unhexlify()` if you have a string.
*   **AP Replacement**: If IT swaps the router, the MAC changes, and your robot breaks. Only use this if auto-select is failing.

### Project 1793: Object-Oriented Professional WiFi (Connect) Class

### 2. Learning Objective
Implement **Captive Portal Detection**. When you connect to "Free WiFi" at a coffee shop, you often can't access the internet until you click "Accept" on a web page. This is a "Captive Portal". We detect this by trying to reach a known site (e.g., Google or a detection endpoint) and checking if we get redirected.

### 3. Concepts Introduced
*   **HTTP 302 Redirect**: The router hijacking your request to show the login page.
*   **Walled Garden**: Being connected to WiFi but blocked from the Internet.

### 4. Hardware Required

### 5. Wiring / Interfaces
*   (Internal)

### 6. Blocks Used

### 7. Variables

### 8. Step-by-Step Guide

**A. Connect**
1.  Wait for WiFi Link.

**B. Probe**
1.  `GET http://connectivitycheck.gstatic.com/generate_204`.
2.  If Result == 204: **Internet OK**.
3.  If Result != 204 (or 200 with Login Page html): **Portal Detected**.

1.  **Pico**: Connects to "Starbucks".

    def check_internet(self):
        try:
            # Android uses this URL to check for portals

### Project 1796: Optimized Professional WiFi (Connect) Algorithm

### 2. Learning Objective
Implement **Power Save Mode**. WiFi radios consume ~100mA+. For battery devices, this is huge. The CYW43 chip supports Power Management (PM) modes where it sleeps between beacons (every ~100ms). This adds latency (ping goes up) but saves energy.

### 3. Concepts Introduced
*   **DTIM Interval**: How often the router wakes up sleeping clients.
*   **Latency vs Power Tradeoff**: Saving battery makes the network slower.

### 4. Hardware Required
*   **Pico W**

### 5. Wiring / Interfaces
*   (Internal)

### 6. Blocks Used
*   **from Comms, drag `wifi_config`**

### 7. Variables
*   **pm**: Power management mode.

### 8. Step-by-Step Guide

**A. Mode 0xa11140**
1.  This is a magic number mapping to `CYW43_PM2_POWERSAVE_MODE`.
2.  `wlan.config(pm=0xa11140)`.

**B. Mode 0xa11142**
1.  This is `PERFORMANCE` mode (No sleep). Better for games/timing.

### 9. Execution Flow
1.  **Performance**: Current ~50mA avg. Ping 5ms.
2.  **Powersave**: Current ~10mA avg. Ping 50ms.

    time.sleep(1)

# Enable Power Saving (Best for battery)
# Note: Magic numbers may vary by SDK version, check docs

wlan.config(pm=wlan.PM_POWERSAVE) 

print("Power Save Enabled. Ping me now.")

### 11. Common Mistakes
